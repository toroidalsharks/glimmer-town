# Notes for Claude working on Glimmer Town

Read README.md first for the folder map and the build. This file covers what isn't obvious from the code.

## The build

- Edit `src/js/*.js`, `src/styles.css` or `src/index.html`. Never edit the top-level `index.html` by hand; `node build.mjs` overwrites it.
- After any change run `node build.mjs --check`, then commit `src/` with the rebuilt `index.html` and `version.json`.
- All files in `src/js` are concatenated in filename order inside one `(() => { 'use strict'; ... })();`. They share one scope. Top-level names must be unique across files (`--check` scans for this, but only at column 0, so keep top-level declarations unindented). Short generic names (`J`, `N`, `P`, `fill`) have collided before; prefer descriptive ones.
- New file: pick an unused number between neighbours (e.g. `615-...`). Start it with the `// ====` banner and a one-line title like the others.
- `560-assets.gen.js` is generated by `tools/blender/assets.py`. Change the Python and run `npm run assets`, never the JS.
- No bundler, no npm packages at runtime. Only three.js r147 and its OrbitControls from jsDelivr (the r147 `examples/js` globals, `THREE.*`), plus two Google Fonts.

## Where it runs

- An old phone lying face up under a Pepper's-ghost hologram box, rendering the town. Another phone is the remote (`MODE === 'remote'`); commands go through `applyCmd` in `140-commands.js`, which is the one door for every player action, local or remote.
- Performance matters. Keep draw calls near 1100 on `pretty`. Graphics levels live in `540-v24-look.js` (`auto / pretty / balanced / lite / classic`); `auto` steps down on slow frames and turns shadows off at the last step. Merge static geometry (`mergeGeos`) instead of adding meshes per prop.
- The post pipeline renders to its own target. It needs `stencilBuffer: true` on that target, or r147 falls back to a 16-bit depth buffer and diagonal stripes appear on the ground when zoomed out.
- Published on GitHub Pages. `build.mjs` stamps a content hash into `BUILD_ID` (`745-auto-update.js`) and writes it to `version.json`. The box and the remote poll `version.json` every 10 minutes and reload onto a new build at a quiet moment, so a push reaches the box by itself within about 15 minutes. Anything that breaks boot also breaks this loop, which is why `npm test` has to pass before pushing.

## Saves and upgrades

- The world `W` saves to localStorage under `glimmer-town-v3` (second island: `-isle2`), and syncs through Firebase when the player has set that up. Device prefs are `glimmer-town-v3-prefs`.
- Old saves must keep loading. New features that need to touch existing worlds use a one-time boot hook guarded by a flag in `W.added` (see `v25Boot` in `630-v25-glue.js`), called from `750-boot.js`. Add a `logUpdate('build', ...)` note there so the player hears about it in the game.

## Secrets and privacy (hard rules)

- The OpenRouter key, Firebase URL and town code are typed into Settings at runtime and stay on the box phone. Never put a key, URL, code or token into any file in this repo. Treat the repo as public, since GitHub Pages usually needs it to be.
- The remote never holds the OpenRouter key. It asks the box, and the box calls the model. Remote links never carry the key.
- ntfy notification settings live only on the box (`glimmer-notify` in localStorage) and are never synced.
- Real internet content (Wikipedia, news) goes through the existing filters. The player can switch it off in the Web tab.

## Real people in the town

Mili (the player's stand-in), Red, Tim, and anyone added as a custom or invited resident (`p.custom`, `p.lovesMili`, `isMili`, `isRealish`) are real people.

- They never get random health conditions and never get moved between jobs by the sim.
- They never commit crimes and are never victims of violent crimes. They can be victims of property crime, sit on juries, or serve as detective.
- Whatever traits the game gives them are portrayed with respect and are never their whole character.
- No health condition, for anyone, is ever used as a crime motive or linked to crime.

## Crime pacing

- Milo asked for one murder a year and means a real year. A game year (28 game days) is only about two and a half hours, so murders run on the real calendar (`S.nextMurderAt`, `635-crime-clarity.js`), with a picker in the Court tab. Don't tie murders back to game days.
- Every misleading clue gets a follow-up clue that rules it out, so a case is always solvable from the board.
- AI models get facts wrong, so in crime scenes the AI only writes feelings and arguments. Every fact (clues, alibis, exhibits) comes from the game's own data, and `factSafe()` in `638-sentences.js` drops AI lines that mention times, places, colors, objects or people outside the case. Keep it that way when adding crime dialogue.

## Testing

- `npm install` once, then `npm test` (build, check, headless boot, a crime from discovery to verdict, a civil case, a wedding) and `npm run shots` for screenshots in `tests/out/`.
- Tests open the built file over `file://`, which turns on `window.__g`, a debug handle with `__g.ev(code)` to run code inside the game's scope. It does not exist on the live site.
- Headless Chromium uses SwiftShader and runs at about 1 fps. Tests set `{ gfx: 'lite' }` prefs, and CSS animations lag. That slowness is the test machine, not the game.
